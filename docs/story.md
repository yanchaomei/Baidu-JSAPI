# 项目故事线

状态：首版故事草案，后续根据接口验证与性能证据收敛。

## 一句话概括

让工业园区的海量空间数据持续流入地图，让调度人员在加载和更新过程中仍能顺畅查看现场。

## 第一幕：冲突

设备、管网和车辆不断产生位置与状态数据。业务人员需要立即看到已到达的数据，同时继续缩放、平移和旋转地图。等待全部下载和解析完成，会延后第一批可见结果；集中处理与上传还可能造成交互停顿。

## 第二幕：洞察

总绘制量之外，数据到达时的处理节奏也决定体验。网络、解析、主线程提交和 GPU 绘制的速度不同；缺少背压与预算控制时，积压会转化为内存增长或突发卡顿。

这一判断需要通过阶段时间线、队列水位和帧时间测量验证。

## 第三幕：方案

计划先打通最小链路：

```text
分块空间数据 → 流式获取 → Worker 增量解析
                              ↓
                        有界待提交队列
                              ↓
                     按帧预算提交 GPU Buffer
                              ↓
                   百度地图 WebGLLayer 增量绘制
```

点对应设备与车辆，线对应管网与运输路径，面对应园区及能源分区。先验证正确对齐、持续显示和资源释放，再扩展规模与优化。

## 第四幕：证据

在相同数据、网络限制、视角、设备及可见要素条件下，对比全量处理、简单分块处理与优化流水线。分别报告首屏、完成时间、吞吐、帧时间、长任务和内存。

性能数字必须来自可复现测试。合成数据演示、真实数据验证和目标设备结果分别标注。

## 第五幕：愿景

把验证有效的流式处理与渲染机制整理为可复用模块，服务于更大范围的设备监控、物流回放和能源态势展示。

AI/Agent 能力作为后续可选扩展，可用于异常说明或辅助分析；是否引入取决于场景价值，并单独测量其资源开销。首阶段优先完成赛题核心渲染链路。

# FlowScape 离线流式渲染性能与验证报告

日期：2026-10-12。本文汇总 120 次正式对照、2 次独立探测、公开接口测试、两种 WebGL 后端的浏览器验证及 40 次辅助资源采样；旧布局的 39 次未完成配置记录单独保留并排除。

**已证实的能力是离线点线面流式管线、控制操作和独立 WebGL 绘制。分块处理明显提前首次绘制命令，但 Worker 与 3 ms 软预算没有稳定胜过简单主线程分块。A40 硬件 WebGL 已实际运行；这不代表百度地图 WebGLLayer 已接通，也不代表赛事交付完成。**

## 2. 模式与测量含义

| 模式 | 数据与解析 | 提交 |
| --- | --- | --- |
| B0 full | 全部读取后，同步解码全部帧 | 使用共享两批队列与绘制内核 |
| B1 main | 主线程按额度惰性解码网络分片 | 无帧预算 |
| B2 worker-basic | Worker 惰性解码，Transferable 交付 | 无帧预算 |
| P worker | 与 B2 相同 | 批次之间检查 3 ms 软预算 |

Buffer 页、Shader、几何生成器及主线程待提交队列一致，队列上限均为 2。3 ms 无法抢占一次 GPU 调用，也不是单帧耗时的硬上限；整个浏览器的网络缓冲、原始 read chunk 和几何内存并不只占两帧。

| 字段 | 本文解释 | 不能据此推导 |
| --- | --- | --- |
| `firstDrawMs` | 从开始会话到首个非零几何绘制调用 | 精确首屏呈现时间；显示器已经扫描出该画面 |
| `streamConsumedMs` | 应用读到 EOF 的时间；含解析、暂停和背压影响 | 纯网络传输结束时间或纯网络带宽 |
| `completeMs` | 所有已解码批次提交结束、会话完成 | GPU 已执行完所有命令 |
| `parseMs` | 解码调用累计 CPU 墙钟时间 | CPU 使用率；独立线程的算力归一化成本 |
| `uploadMs` | 主线程消费与提交调用累计墙钟时间 | GPU 执行耗时或 GPU 使用率 |
| `frames.p95Ms/p99Ms` | 对该阶段采集的 rAF 时间戳间隔取分位数 | GPU timer query；显示器实际呈现帧率；用户输入延迟 |
| `frames.fps` | 最近最多 60 个 rAF 间隔的采样率 | 全阶段平均 FPS 或系统显示器 FPS |
| `gpuBytes` | 本图层分配的 Buffer 字节 | 全系统显存或全部 GPU 资源 |
| `jsHeapBytes` | 浏览器可提供时的 JS 堆快照 | 进程 RSS、峰值内存；精确且跨浏览器可比的分配量 |

以下表格按配置给出 **5 次的中位数 [最小值–最大值]**，时间单位为 ms。每次运行先计算自己的帧分位数，再在 5 次之间汇总；未将所有帧合并为单一分布。仅一个固定种子、每配置 5 次，未进行显著性检验或声称总体分布收益。

## 5. 对照结论与负结果

变化率定义为 `(方案中位数 / 基线中位数 - 1) × 100%`；负数表示时间减少，正数表示更慢。相对差值仅比较同一台机器、同一数据配置。

| 环境与场景 | main 首绘相对 full | worker 首绘相对 main | worker 完成相对 main |
| --- | ---: | ---: | ---: |
| 软件 WebGL：点规模 / 10,000 点 | -74.2% | +83.1% | +31.2% |
| 软件 WebGL：点规模 / 100,000 点 | -92.2% | -29.7% | +4.0% |
| 软件 WebGL：点规模 / 1,000,000 点 | -99.4% | +95.9% | +7.1% |
| 软件 WebGL：海量线面混合 / 10,000 点 | -96.0% | +69.4% | +3.3% |
| A40 硬件 WebGL：百万点 / 1,000,000 点 | -98.7% | +100.9% | +1.7% |
| A40 硬件 WebGL：最大混合参数 / 2,000,000 点 | -99.3% | +35.7% | -0.2% |

1. **增量获取和提交能提前首次绘制命令。** A40 百万点中 full 首绘中位数 2,452.7 ms，main 32.1 ms，worker 64.5 ms；main 比 full 减少 98.7%。软件百万点 main 14.7 ms，full 2,323.4 ms。这支持分块链路改善命令提交等待，但不替代纯网络结束和精确呈现测量。由于先生成面、再线、最后点，首批往往是面，不是首批设备点。
2. **当前 Worker 不是稳定优于简单分块的方案。** A40 百万点 main 完成中位数 2,287.0 ms，worker-basic 2,322.8 ms，worker 2,326.3 ms；worker 比 main 慢 1.7%，且首绘更慢。软件百万点 worker 比 main 完成慢 7.1%，软件混合慢 3.3%。软件 10 万点 worker 首绘较 main 快 29.7%，但完成仍慢 4.0%。不能只挑选该首绘收益宣称全面提升。
3. **3 ms 软预算尚无稳定的额外收益证据。** 软件百万点 worker 完成 11,062.5 ms，worker-basic 10,611.9 ms；A40 百万点分别为 2,326.3 和 2,322.8 ms，且多数 rAF 指标接近采样刷新间隔。可能成本包括 Worker 启动、跨线程调度和当前批次粒度；这些是待验证解释，未测出因果分解。最小后续实验应固定主线程基线，单独扫描批大小与提交预算。
4. **软件 WebGL 的大点规模受全量绘制负载限制。** 百万点的稳态 P95 中位数为 416.7–533.3 ms，而 A40 同规模记录为 16.7–16.8 ms。两环境的硬件与浏览器不同，不能据此给出受控 GPU 加速比；可得的结论是本轮软件执行环境不适合证明百万点高帧率。任何模式通过数量正确性都不等于流畅性通过。
5. **A40 最大混合通过这次离线对照，但 Worker 优势仍有限。** 四模式各 5 次，全部完成 3,000,000 顶点与 50 次绘制调用/帧。main 完成中位数 5,294.7 ms，worker-basic 5,272.8 ms，worker 5,283.1 ms；worker 比 main 仅减少 0.2%，范围重叠。worker 首绘 57.4 ms，比 main 42.3 ms 慢 35.7%；worker-basic 29.0 ms。全量稳态 rAF 采样率接近 60 Hz，但不足以证明真实地图交互延迟、GPU 命令完成或长期稳定性。
6. **P95 会掩盖集中解析的单次停顿。** A40 百万点 full 的加载 P95 中位数为 16.8 ms，但每次最大 rAF 间隔中位数 133.3 ms [116.6–150.0]；A40 最大混合 full 对应 16.8 ms 与 300.0 ms [299.9–316.6]。main 最大混合的最大间隔为 50.0 ms [33.4–66.6]，worker-basic 为 33.3 ms [33.2–50.0]，显示集中解析尖峰需要单独审视，不能只报 P95 或末段 rAF。
7. **离群值和观测异常保留。** 软件 1 万点 full 的首绘范围 56.3–510.6 ms，混合 full 的完成范围 630.9–1,409.1 ms，未删除首轮或最慢值。冷启动与环境扰动是可能解释，尚未定位。A40 百万点 full 的同步 `parseMs` 中位数 119.0 ms、最大混合 full 为 283.9 ms；百万点 full 记录的长任务计数仍均为 0，最大混合 full 为 0–1；不能据“0”宣称无主线程阻塞，需性能轨迹核对观察器事件与帧时间口径。

## 9. 尚未闭合的门槛与最小下一步

- **百度业务图层：** 获取本人授权浏览器 AK、来源白名单、赛题指定 SDK 与公开回调/坐标/matrix 合同，再检查点线面与底图在缩放、平移、旋转、倾斜及生命周期下的对齐。当前所有结果均为离线独立 WebGL；`baiduWebGLLayerAccepted=false`。
- **性能归因：** 用同一目标设备的性能轨迹和输入事件时间戳复核主线程阻塞及交互延迟；若需要 GPU 执行时间，单独引入可用且经过验证的 timer query，不能拿 rAF 代替。
- **完整测量：** 当前没有纯网络结束时刻、每批端到端可见延迟、按时间窗的网络/解析/提交吞吐、精确呈现时间和进程内存峰值证明。外部资源窗口只有部分运行，尚缺模式与阶段对齐、出生/退出进程补全及专用设备归因；不要把辅助 CPU/GPU 采样或 JS 堆快照填成完整的每模式资源结果。
- **支持规模：** 在明确帧时间、正确性、内存和长时稳定性门槛后，再逐级寻找可接受规模；一次参数上限完成不能替代该判定。
- **方案保留条件：** 先保留 main 简单基线。只有 Worker 或软预算在同数据、多次重复和目标交互指标上有可复现收益时，才将其作为性能优势；现有负结果不删除。
- **交付：** 真实百度模式、目标浏览器前台交互、持续更新/位置变化、演示视频、赛事提交包与正式提交仍需分别验收。

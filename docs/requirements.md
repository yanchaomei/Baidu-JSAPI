# 赛题要求与验收映射

本文根据 2026-10-12 提供的赛题说明整理，并与 [主办方正式三页任务书](https://apiv1.oschina.net/api/files/fhhc7e8z6no3gyt/l6b4luq8g5y7v3y/ai_jsapi_xxcl7CJCuY.pdf) 对照核验。接口附件核验记录见 [官方资料调研](research/webgllayer.md)。

## 问题定义

工业园区、能源设施与物流网络需要持续展示大量设备、车辆、人员、管线和业务分区。数据规模增长后，全量下载、集中解析和集中渲染可能增加等待时间、阻塞主线程，并影响地图交互。

本项目需要验证：把获取、解析和渲染组织为可控的增量流水线，并配合 GPU 批量绘制，能否在相同数据和硬件条件下改善首屏与加载期间的交互表现。

## 必须满足的交付

| 编号 | 要求 | 验收证据 | 当前状态 |
| --- | --- | --- | --- |
| D1 | 完整 Web 应用，基于百度地图 JSAPI WebGLLayer | 可运行 Demo、地图集成记录 | 独立 Demo 已运行；百度图层未验收 |
| D2 | 支持大规模点、线、面 | 三类几何分别展示与混合展示 | 独立 WebGL 已验证，见报告 |
| D3 | 持续加载和增量显示 | 首批可见时间早于下载及解析全部完成 | 增量截图与流读取阶段已验证；网络独立完成时间未采集 |
| D4 | 流式加载、解析、调度、缓存与提交 | 模块说明、时间线、队列和取消行为记录 | 获取、惰性解析、背压、提交和取消已验证；无跨运行缓存 |
| D5 | 高性能 WebGL 渲染 | Buffer 管理、绘制批次、Shader 与上传开销记录 | 独立 NVIDIA A40 渲染与重复测试已完成；百度层待验收 |
| D6 | 持续处理时仍可缩放、平移、旋转 | 固定交互脚本下的 FPS、帧时间和长任务数据 | 离线软件与硬件相机轨迹已测；真实地图与输入延迟待测 |
| D7 | 代表性工业场景 | 工业园区设备与管网监控演示 | 合成工业园区可运行 |
| D8 | 完整性能测试报告 | 多规模、多阶段、同条件对照及原始数据 | 120 次正式运行与资源辅助采样已记录；真实地图及完整进程归因缺口明确 |

Fetch Stream、Web Worker、WASM、Instanced Rendering 等是可选技术手段。是否采用应依据兼容性与测量结果，避免为了罗列技术而增加模块。

## 评分与优先级

| 维度 | 权重 | 开发关注点 |
| --- | --- | --- |
| WebGL 高性能渲染 | 40% | 数据组织、GPU Buffer、批量绘制、Shader、稳定帧率 |
| 流式数据处理 | 25% | 获取到显示的增量链路、首屏、吞吐、可控队列 |
| 实时交互与系统性能 | 20% | 加载与更新期间的缩放、平移、旋转表现 |
| 工业场景与工程实现 | 15% | 场景可信度、完整 Demo、技术说明与测试结果 |

## 性能报告覆盖范围

- 首屏数据展示时间。
- 数据持续加载速度。
- 数据增量渲染效率。
- 最大支持渲染规模及达到限制的条件。
- 地图交互过程中的 FPS。
- 数据加载过程中的 FPS。
- CPU 使用率。
- GPU 使用率。
- 内存占用。

浏览器无法直接提供或当前环境无法可靠采集的指标，应注明采集限制。不能将缺失数据填写为零，也不能将帧时间当成 GPU 使用率。

测量定义与对照约束见 [性能测试计划](performance.md)。

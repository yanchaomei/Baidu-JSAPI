# 开发路线图

路线图中的规模均为计划测试档位，不能视为已支持能力。

- [x] 赛题要求、评分映射、五幕故事线。
- [x] 分阶段路线图与性能测试计划。
- [ ] 完成首个可运行 Demo。

## M1：接口与最小链路验证

- 核实百度地图 JSAPI WebGLLayer 官方接口、运行条件、坐标系统和生命周期。
- 配置浏览器端应用 AK 的方式与来源限制，提供占位配置。
- 在真实地图上绘制少量点、线、面，验证缩放、平移、旋转时的空间对齐。
- 打通分块获取、Worker 增量解析、首批提交与取消加载。
- 记录首批可见、下载完成和解析完成时间。

验收门槛：真实 WebGLLayer 集成可运行；三类几何位置正确；首批数据在全量处理结束前可见；取消后资源能够回收。

## M2：规模与渲染优化

- 建立固定随机种子、固定范围和明确几何复杂度的合成数据集。
- 从小规模验证开始，逐步测试 10 万、100 万及更高规模。
- 探索 Buffer 分配与复用、批量绘制、实例化和数据上传优化。
- 加入有界队列、背压、每帧提交预算与数据缓存。
- 验证持续状态更新及位置变化。

验收门槛：保留相同渲染工作的对照结果；明确吞吐、内存与交互之间的取舍；不以减少显示内容冒充同规模性能提升。

## M3：工业场景 Demo

- 完成设备点位、管网状态和区域分布的统一场景。
- 展示加载进度、已处理要素数、更新状态与性能观测。
- 支持暂停、继续、取消与重新加载，验证重复操作后的资源使用。
- 明确合成数据标识与展示边界。

验收门槛：可重复演示「持续流入、逐步显示、持续交互」全过程。

## M4：交付与复现

- 完成同条件对照、多规模、多加载阶段与固定交互测试。
- 保存原始测量数据、环境清单和复现步骤。
- 完成技术文档、性能报告与演示材料。
- 核实主办方正式提交要求后整理交付包。

## 调整与停止条件

- WebGLLayer 接口或运行条件不满足预期时，先解决集成问题，再扩展规模。
- 简单分块基线已达到相同效果时，保留结果并简化方案。
- 新优化无法稳定改善目标指标，或明显恶化内存与交互时，撤回该优化并保留实验记录。
- 最大规模以预先定义的正确性、帧时间、内存和稳定性门槛共同判断。
